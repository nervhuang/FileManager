# 作者／團體域

[`app/authors/`](../../app/authors/)，分兩層。

| 檔案 | 依賴 Qt | 職責 |
|---|---|---|
| `db.py` | 否 | `authors.db` 的結構、查詢與異動日誌 |
| `names.py` | 否 | 「團體 (作者)」貼上拆分 |
| `labels.py` | 否 | 類型的顯示字串（面板與兩個對話框共用）|
| `panel.py` | 是 | 面板與樹 |
| `edit_dialog.py` | 是 | 新增／編輯單一作者或團體 |
| `changes_dialog.py` | 是 | 最近變更與還原 |
| `icons.py` | 是 | 面板工具列的自繪圖示 |

不依賴 Qt 的那三個是服務層：Hermes MCP server 與 CLI 兩個進程也讀寫 `authors.db`。

---

## 資料庫

**AUT-1** `authors.db`（SQLite，WAL）是作者與團體的**單一真實來源**。
GUI、MCP server、CLI 三者讀寫同一個檔案，位置由 [settings.md](settings.md) 的 SET-1 決定。

**AUT-2** 單一 `entities` 表，以 `type` 區分作者／團體；別名獨立表；
作者⇄團體為多對多關聯。

**AUT-3** 每一次寫入都記錄到 `changes` 表，含前後快照。
刪除為**軟刪除**。任何來自 Hermes 的誤動作都能從 GUI 的「最近變更」還原。

**AUT-4** `english_name` 欄位為純中繼資料，僅供網站查詢反查用，不參與本機檔案比對。
未提供時保持原值不動，不會被空字串覆寫。

**AUT-5** 資料庫具備欄位遷移能力：缺少 `english_name` 時自動 `ALTER TABLE` 補上，
舊版 `authors.db` 可直接沿用。

**AUT-6** 關鍵字查詢同時比對名稱、別名與 `english_name`，皆為大小寫不敏感（`COLLATE NOCASE`）。

**AUT-7** `linked_names` 為**新增合併**語意，不是整組取代。
送出部分關聯不會清掉既有的其他關聯。

## 面板

**AUT-8** 樹狀顯示團體及其旗下作者。單擊任一項目開一個搜尋分頁，
查詢字串由該項目的名稱加上它的**每一個別名**組成。

**AUT-9** 「作者」群組**列出全部作者**，含已歸屬團體者。已歸屬者同時出現在團體底下。
這樣群組標題的數字才與實際列出的筆數相符，也讓任何作者不必展開團體就能直接找到。

**AUT-22** 樹的兩個**最上層節點**（「團體」「作者」）按右鍵，選單提供檢視切換：
「全部」與「僅顯示無英文名稱」，兩者互斥並打勾標示目前狀態。英文名稱只在對外查詢時
用得到（AUT-4），沒填的那幾筆更新檢查器就抓不到；但一份四百筆的清單，
沒有這個檢視就只能一筆筆點開看。

**AUT-22a** 切換是**整個面板一個狀態**，不是每個群組各一個。目的是盤點「還有哪些沒填」，
兩個群組各切一次只會讓人以為自己漏了一邊。所以在哪一個最上層節點按右鍵都切同一個狀態。

**AUT-22b** 判準是**節點自己的** `english_name` 是否為空（`NULL` 與空白字串等價）。
團體底下的作者也各自判斷：有英文名的團體在這個檢視裡不出現，它旗下沒填的作者仍然
列在「作者」群組（AUT-9 作者一律全列），所以不會有任何一筆因為父節點被濾掉而消失。

**AUT-22c** `english_name` 空白**還不夠**：名稱本身就是拉丁字母的（`MAFIC`、
`blue soda`、`Panda Boxing`）不算缺，直接拿名字查就行。實測 443 筆裡有 6 筆是這樣，
把它們列進盤點清單看起來就是功能壞了。

判準是 `names.is_latin_name`，只認半形可列印 ASCII 且至少有一個英文字母；
帶重音的拉丁字母（`Café`）判為缺，留在清單裡等人確認。**這支判準與更新檢查器的
`tag_for()` 共用同一份**（見 [checker.md](checker.md)）：一邊說「這筆不缺英文名」、
另一邊卻照樣跳過不掃，那份盤點清單就在說謊。

**AUT-23** 篩選開著時，群組標題必須說出來：`團體（12，僅無英文）`。
少了這個提示，清單少一半看起來就是資料掉了。

**AUT-24** 這個檢視**不寫進設定檔**，每次啟動都是「全部」。開機看到清單默默少一半，
第一個反應會是資料庫壞了，不是「喔我上次切過」。

**AUT-10** 工具列六個動作：新增作者／新增團體／編輯／刪除／重新整理／最近變更，以分隔線分組。

**AUT-11** 編輯與刪除在沒有選取時為停用狀態。

**AUT-12** 面板預設寬度 660px（六個按鈕剛好排得下），下限 80px；
實測最小 sizeHint 為 151px。顯隱與寬度持久化，見 [settings.md](settings.md) 的 `[Layout]`。

**AUT-13** 面板以 `Ctrl+Shift+A` 切換顯隱，見 [ui-shell.md](ui-shell.md) 的 SHL-15。

**AUT-14** 面板與其對話框都跟隨應用程式字型。
Qt 在頂層視窗邊界停止字型傳播，對話框必須自己套用，不會從面板繼承。

## 新增／編輯對話框

**AUT-15** 欄位：名稱、類型、別名、關聯對象、備註、英文名稱。

**AUT-16** 按下 OK 時，別名／關聯輸入框裡**尚未按 Enter 的文字必須先提交**。
否則使用者打完字直接按 OK，內容會被丟掉。

## 「團體 (作者)」貼上自動拆分

**[未驗]** 以下條文由程式碼逆向寫出（commit `ae89452`、`bd80b87`），任何既有文件
都沒有記載，**請確認是否符合原意**。實作在 [`app/authors/names.py`](../../app/authors/names.py)，
行為已由 `tests/authors/test_aut_17_parse_circle_author.py` 鎖住——但測試鎖的是
「現在怎麼跑」，不是「應該怎麼跑」。條文確認後若有出入，先改規格與測試。

**AUT-17** 名稱欄輸入符合「團體 (作者)」格式時，自動拆成團體名 ＋ 旗下作者，
沿用既有的 `linked_names` 路徑寫入，建立雙向關聯。

**AUT-17a** **只在「新增」模式攔截**。編輯既有項目時不得拆分 ——
既有項目的名稱本身可能合法地含有括號。

**AUT-18** 格式細節：

| 項目 | 規則 |
|---|---|
| 外層方括號 | 可有可無（`[團體 (作者)]` 與 `團體 (作者)` 皆可） |
| 內層括號 | 半形 `()` 或全形 `（）` 皆可 |
| 括號內作者數 | 不限，以頓號 `、`、半形逗號 `,`、全形逗號 `，` 分隔 |
| 空白 | 各段前後空白皆忽略 |

**AUT-19** 取**字串尾端最後一組括號**（正則以 `$` 錨定）。
團體名本身含括號時才不會被錯拆。

**AUT-20** 內層括號不得再含括號（作者段的字元集排除 `()（）`）。

**AUT-21** 拆解後團體名為空、或作者清單為空，視為不符合格式，
維持原樣不做任何拆分，不得報錯。
