# 檔案操作域

[`app/fileops/`](../../app/fileops/) 收下所有原生呼叫；編排仍在
[`app/file_manager.py`](../../app/file_manager.py) 與 [`app/views.py`](../../app/views.py)
的 `_ShellDropMixin`。

| 檔案 | 依賴 Qt | 職責 |
|---|---|---|
| `shell.py` | 否 | `SHFileOperationW`（搬移／複製／回收筒）、原生右鍵選單、右鍵拖放、建立捷徑 |
| `rename.py` | 否 | 改名的判定（該不該做、目標是什麼、不行的話為什麼）|
| `clipboard.py` | 否 | 路徑正規化、去重、貼上要搬還是要複製 |
| `drag_menu.py` | 是 | `IDropTarget` 不可用時的後備選單 |

`shell.py` 只認路徑與視窗代號（hwnd），成功與否用回傳值表達。訊息呈現與後續
刷新都留在呼叫端——同一個失敗在主視窗與在拖放時的措辭不同，要刷新的東西也不同。

**兩個面板不再各有一份實作。** `SHFILEOPSTRUCTW` 曾經被定義三次，
建立捷徑、右鍵拖放、後備選單也各有兩份。重複的程式碼分頭演化，FOP-15a 記的
那個 bug 就是這樣來的。

**這一域大部分行為在 CI 上驗不了**：Windows shell COM、原生右鍵選單、右鍵拖放、
回收筒，全部需要真實 shell。凡是 **[手動]** 的條文，自動測試只能覆蓋路徑計算與前置判斷，
實際效果必須人工驗收。

---

## 選取

**FOP-1** 檔案面板與搜尋面板皆為 `ExtendedSelection`（可多選）。

**FOP-2** 按在**已選取的項目**上時保留整組選取，不得塌陷成單一項目。
接著拖曳即拖動整組選取。

> Qt 的預設行為：按在已選取項目上時 view 留在 `NoState`，
> 第一次滑鼠移動會被當成框選而覆蓋掉多選。因此本域自行偵測移動距離
> （`QApplication.startDragDistance()`）並手動啟動拖曳。

**FOP-3** 只點擊、不拖曳時仍塌陷成單一項目（維持一般點選語意）。

**FOP-4** `startDrag` 讀取的是完整選取，確保一次拖曳所有選取的檔案。

---

## 剪貼簿

**FOP-5** 支援複製、剪下、貼上，作用於**目前有焦點的**面板。

**FOP-5a** 貼上時，**只有在剪貼簿內容仍然是我們剪下的那一批**才搬移。
中間只要有別的程式寫過剪貼簿，就退回複製。

> 這條規則的代價不對稱：判成複製最多是多一份檔案，判成搬移卻會動到使用者
> 只想複製的東西。不確定時一律複製。
> **[未驗]** 比對目前是順序敏感的，同一批但順序不同會退回複製——偏安全的方向。

**FOP-6** 剪貼簿內容採 Windows 原生檔案格式（`QMimeData` 的 URL 清單），
與檔案總管互通。同一個檔案在剪貼簿裡重複出現時只處理一次。

---

## 刪除

**FOP-7** 刪除一律送**回收筒**，不做永久刪除
（`SHFileOperationW` + `FO_DELETE` + `FOF_ALLOWUNDO`）。

**FOP-8** 送出前先濾掉已不存在的路徑；全部都不存在時不執行操作。

**FOP-9** `FOF_WANTNUKEWARNING`：無法送回收筒（例如超過容量、網路磁碟）時，
由系統顯示警告，不得靜默永久刪除。 **[手動]**

---

## 重新命名

**FOP-10** 新檔名為空、或與原檔名相同時，還原顯示、不執行操作、不報錯。

**FOP-11** 檔名含 `\ / : * ? " < > |` 任一字元時拒絕並提示，還原顯示。

**FOP-12** **僅大小寫不同的更名必須成立**。Windows 的 `os.path.exists` 大小寫不敏感，
正在被改名的檔案本身不得被當成名稱衝突。

> 這一條曾經是壞的，修好之後一直沒有測試守著。判定現在在
> [`app/fileops/rename.py`](../../app/fileops/rename.py)，由
> `tests/fileops/test_fop_10_12_rename.py` 涵蓋——包含「目標是另一個檔案時，
> 大小寫不同也要擋」這個反向情境，否則測試會被一個「永遠放行」的實作騙過去。

**FOP-13** 程式自身觸發的更名不得再遞迴觸發模型的變更處理
（以 `_search_item_rename_in_progress` 旗標阻擋）。

**FOP-14** 在檔案面板新建資料夾後，自動聚焦該資料夾並進入更名編輯狀態。

## 拖放

**FOP-15** 左鍵拖放：交由 Qt 內建機制偵測並呼叫 `startDrag()`（多選情況見 FOP-2）。

**FOP-15a** 交給 `SHFileOperationW` 的路徑**必須先 `os.path.normpath`**。

Qt 給的路徑是正斜線：`QUrl.toLocalFile()` 與 `QFileSystemModel.filePath()`
在 Windows 上都回 `D:/a/b.txt`。實測結果：

| `pFrom` | `pTo` | 結果 |
|---|---|---|
| 反斜線 | 反斜線 | 成功 |
| **正斜線** | 反斜線 | 成功 |
| 反斜線 | **正斜線** | **錯誤碼 183，檔案不動** |
| 正斜線 | 正斜線 | **錯誤碼 183，檔案不動** |

**關鍵是 `pTo`（目標目錄）**，`pFrom` 容忍正斜線。這也解釋了為什麼刪除到回收筒
不受影響——`FO_DELETE` 的 `pTo` 是 `None`。

> 這條規則曾經只有一半成立：主視窗的 `_perform_file_op` 有正規化，
> `views._apply_drop_operation` 沒有，於是左鍵拖放搬檔案一直是失敗的，
> 而且錯誤碼 183 走的是「已存在」分支，連警告都不跳。
> 兩份實作除了這一行以外完全相同——重複的程式碼分頭演化，正是這樣出事的。
> 現在只有 `fileops.shell.move_or_copy` 一份實作。

**FOP-16** 右鍵拖放：叫出 Windows 原生的「複製到／移動到／建立捷徑」選單。 **[手動]**

**FOP-17** 原生選單無法叫出時，退回本程式自繪的同等選單，功能不得缺少。 **[手動]**

**FOP-18** 拖曳中滑到清單邊緣時自動捲動。 **[手動]**

**FOP-19** 落點解析要能區分「放在某個資料夾上」與「放在空白處（＝目前目錄）」。

## 原生右鍵選單

**FOP-20** 檔案面板與搜尋面板的右鍵選單為 Windows 原生 shell 選單
（`IContextMenu`），不是自製選單。 **[手動]**

**FOP-21** `IContextMenu2` 在部分項目上會失敗（探測腳本
`scripts/probe_shell_context_menu.py` 已記錄 `-2147467263 未實作`）。失敗時退回 `IContextMenu`，不得讓選單完全打不開。 **[手動]**

---

## 操作後的重新整理

**FOP-22** 建立／刪除／更名／移動後**不得有 2–3 秒的 UI 凍結**。
達成方式見 [search.md](search.md) 的 SRCH-17、SRCH-19 到 SRCH-21。

**FOP-23** 操作涉及的目錄加入檔案系統 watcher，外部變更也會反映。
操作結束後解除追蹤，不得無限累積 watcher。

**FOP-24** 排程式的面板重新整理（多段延遲重試）用於等待 shell 操作完成，
同一批操作不得重複觸發完整搜尋。
