# 外殼：字型、版面、工具列

目標位置：`app/file_manager.py` 拆分後只剩這一層 —— 建立各功能域面板、把訊號接到槽、
管理版面。**外殼不得包含任何功能域的商業邏輯。**

---

## 字型

**SHL-1** 字型級數以 `Ctrl+=` / `Ctrl++` / `Ctrl+Num++` 放大、對應鍵縮小，每次 1pt，
範圍 6–72pt。狀態列顯示目前級數。

**SHL-2** 字型設定套用於**整個應用程式**，包含功能表列、狀態列與所有工具列文字。

**SHL-2a** 判準是**相對追蹤**，不是絕對相等：字級加 N，每個 widget 的字級都加 N。
有些差距是刻意的——工具列按鈕釘在比內文大兩級（圖示與文字的比例）、
更新檢查器的計數列大一級、執行紀錄等寬且小一級。要求它們等於基準字級是錯的判準。

> 這條規則曾經整片失守：只套用到檔案／搜尋清單、兩個分頁列、兩個資訊 combobox、
> 麵包屑列與兩個面板。2026-08-24 實測，拉到 21pt 時功能表列、狀態列、
> 三條工具列與主視窗本身全都停在 12pt。

**SHL-3** 字型套用採**遞迴走訪**（`app/font_scaling.py`），新增的面板自動涵蓋，
不需要任何人記得回來登記。

> 曾經的作法是 `_apply_font_size` 裡一份手寫白名單。作者面板因為漏登記而完全不隨
> Ctrl+= 縮放（CHANGELOG 2026-08-16），更新檢查器面板是第二次補登記。
> 這是「功能與架構未劃分」最典型的形態：橫切關注點寫成神類別裡的一份清單。

**SHL-3a** 遞迴必須**先量完全部、再統一套用**，不可邊走邊改。
`setFont` 會往下傳播到還沒明確設過字型的子 widget，邊走邊改的話往下每一層讀到的
都已經是新值，偏移量會一層層疊上去——實測 12pt 的樹，底層會一路被砍到 6pt 下限。

**SHL-3b** 遞迴**不得動 `QApplication.setFont`**。那是全域可變狀態，會讓套用變成
順序相依。對話框本來就得自己套用字型（見 [authors.md](authors.md) 的 AUT-14）。

**SHL-3c** 縮放必須**可逆**：放大再縮回原本的字級，每個 widget 都要回到原值，
包含中途撞到 6pt 下限的情況。

**SHL-4** 另有一支測試遞迴掃過主視窗底下所有 widget，任何一個字型不等於目標級數即紅燈。
即使 SHL-3 已改成遞迴，這支測試仍保留 —— 它守的是「有 stylesheet 的 widget 阻斷傳播」這類例外。

**SHL-5** 設了 stylesheet 的 widget，Qt 視其字型為「已明確指定」，父層字型不再傳下去。
麵包屑列（本體、麵包屑按鈕、編輯框各自帶 stylesheet）因此必須逐一套用，
且導覽後重建的麵包屑也要繼承。

**SHL-6** 麵包屑列高度隨字型成長，不固定在 30px 最小值。
實測 13pt → 30px，21pt → 38px。

**SHL-7** 分頁關閉鈕的 `✕` 隨字型縮放。尺寸取自分頁列的 `fontMetrics`
（`max(16, round(height * 0.78))`），而非樣式的 `PM_TabCloseIndicator*` 度量，
並在新增分頁與字型改變時重新套用。

**SHL-8** `✕` 的繪製由 proxy style 負責，且**掛在按鈕上、不是掛在分頁列上** ——
`QWidget::setStyle` 不會傳到子項，掛在分頁列上時關閉鈕用的仍是應用程式樣式。
proxy style 物件必須留參考：`setStyle` 不接手所有權，被回收會在繪製時崩潰。

**SHL-9** 字型改變後 `_sync_right_header_spacing` 必須在麵包屑列**重新調整高度之後**
再算一次，否則右側搜尋面板的分頁列會沿用舊高度而錯開幾個像素。

## 工具列與圖示

**SHL-10** 三條工具列（檔案面板、作者面板、更新檢查器面板）圖示尺寸一律 64×64，
高度互相對齊且釘死，不得因 `sizeHint` 差異而漂移。

**SHL-10a** 釘死的高度必須**隨字型重算**，否則放大後的按鈕文字會被裁掉。
判準：任一工具列的 `height()` 不得小於它的 `sizeHint().height()`。

> 這條規則是 SHL-2 的直接後果。高度原本在建構時算一次就固定，那個年代工具列
> 文字不隨字型縮放，所以不會出事。文字開始跟著長大之後，實測 18pt 時檔案面板
> 與作者面板的工具列各需要 107 與 111px，卻都還釘在 102px，「新增作者」被切掉
> 半個字。重算的實作在 `font_scaling.sync_toolbar_heights()`：先解除釘死再讀
> `sizeHint`，釘死狀態下讀到的是被限制後的值，不是內容需求。

**SHL-11** 所有工具列圖示在 64px 下實際渲染尺寸必須是 64×64
（判定方式：`icon.actualSize(QSize(64,64)) == QSize(64,64)`，
排除 `objectName` 為 `qt_toolbar_ext_button` 的溢位鈕）。

> 這條規則曾經失守：更新檢查器的「停止掃描」用 `QStyle.SP_MediaStop`，
> 實測只有 32×32，同工具列其餘五個皆 64×64——與當初 `SP_BrowserReload`
> 只出 24/32px 完全同類，而既有解法 `widgets.make_refresh_icon()` 沒被沿用。
> 已改為自繪的 `checker.icons.make_stop_icon()`，並由
> `tests/shell/test_shl_11_toolbar_icon_sizes.py` 遍歷全部工具列按鈕把關。

**SHL-12** **不使用 Qt 內建圖示。** 全部工具列圖示自繪，集中在 `app/icons.py`
（外殼共用）、`app/checker/icons.py`、`app/authors_panel.py`（各功能域自己的）。

> 內建圖示的尺寸問題（只出到 32×32）其實只影響少數幾顆，真正的問題是外觀：
> Windows 的立體光澤風格與自繪的實心填色語彙擺在同一條工具列上，一眼就看得出
> 是兩套東西。曾經同時混著三種——線稿（剪下／複製／貼上／重新命名）、
> 實心填色（資料夾／排列／重新整理）、Windows 系統（上一頁／下一頁／
> 新增資料夾／垃圾桶）。

**SHL-12a** 視覺語彙為**實心填色 ＋ 深色描邊 ＋ 高光**，不是線稿，也不是
Windows 的立體光澤風格。同一條工具列裡混用兩套語彙一眼就看得出來。

> 更新檢查器的工具列曾經是這樣：兩顆自繪的扁平圖示，加上兩顆 Windows 系統圖示
> （有光澤的文件、立體掃把）。已全部改為自繪的 `checker.icons` ——
> `make_detail_icon()`（瀏覽器視窗裡的縮圖牆）與 `make_reset_icon()`
> （紀錄紙加紅色回轉箭頭）。

**SHL-12b** 回轉箭頭要把環與箭頭畫成**同一條封閉路徑**。分成兩個圖形畫，
接合處無論怎麼對齊都會留下看得見的縫。見 `checker.icons._ring_arrow_path()`
與 `widgets.make_refresh_icon()`。

**SHL-12c** 圖示裡的徽章要畫得夠大。實測 64px 的圖示裡放一個 26px 的徽章，
「環＋缺口＋箭頭」三層細節會糊成一個白色的 C，看不出是回轉箭頭。 **[手動]**

**SHL-13** 工具列建於 `QToolBar` 而非固定 `QHBoxLayout`，面板變窄時按鈕折進溢位選單，
不得把最小寬度往上推。實測：檔案面板工具列最小寬 94px、作者面板 151px。

> 曾經的缺陷：固定 `QHBoxLayout` 造成 1506px 最小寬，往上傳播到中間面板，
> 使作者面板的分割握把在視窗小於 1657px 時完全拖不動。

**SHL-14** 按鈕採「圖示在上、文字在下」，兩條工具列外形一致。

## 面板顯隱與版面

**SHL-15** 作者面板以 `Ctrl+Shift+A` 切換顯隱。**不可用 `Ctrl+L`** ——
麵包屑列已用 `Ctrl+L` / `Alt+D` 聚焦路徑編輯框，兩個動作綁同一組合鍵會變成模糊快捷鍵。

**SHL-16** 右側面板可切換水平／垂直配置，兩種配置的分割尺寸各自持久化（見 SET-6）。

**SHL-17** 面板顯隱與寬度於關閉時寫入設定，下次啟動還原。

## 拆分注意

- 外殼只准做三件事：建立面板、接線、管理版面。任何 `if` 判斷牽涉到某個域的商業規則，
  就代表那段程式碼放錯地方。
- 域與域之間**不得互相 import**。跨域互動一律走 Qt 訊號，由外殼接線。
  現有 `AuthorsPanel.search_requested`、`CheckerPanel.detail_requested` /
  `status_message` 就是正確範例。
